# Markdown 知识库规范

## 条目组织

每篇文档围绕一个知识点展开。使用 UTF-8 编码和清晰的 Markdown 标题，避免将多本书的 OCR 内容合并成一篇文档。正文应能独立理解，不能只写“同上”“见图”而缺少上下文。

## 元数据

使用 [模板](../templates/knowledge-entry.md) 顶部的 YAML 元数据：

| 字段 | 含义 |
| --- | --- |
| `id` | 稳定且唯一的条目 ID；修改标题时仍保持不变 |
| `title` | 知识点标题 |
| `subject` | 对应目录的科目标识 |
| `chapter` | 所属章节 |
| `tags` | 检索关键词列表 |
| `exam_year` | 适用考试年份，未知时为 null |
| `source_type` | original-note、pdf-extract 或 external-reference |
| `source_title` | 原始资料标题 |
| `source_pdf` | 相对仓库根目录的 PDF 路径，无 PDF 时为 null |
| `source_pages` | PDF 文件实际页码列表，从 1 开始；书内印刷页码另行说明 |
| `source_url` | 原始来源网址，无网址时为 null |
| `reviewed` | 是否完成人工校对；OCR 初稿为 false |
| `updated_at` | 最近更新日期，格式 YYYY-MM-DD |

## 正文格式

- 公式使用 `$...$` 或 `$$...$$`，写明变量、单位和成立条件。
- 代码块注明语言，表格使用 Markdown 表格。
- 图示需要保留图片或 PDF 页码引用，并补充文字说明；截图中的内容不能仅靠图片名称检索。
- 题目、答案、推导和个人总结分别标明。不要把推测内容写成原文结论。
- 资料存在不同版本时注明版本；校对未完成的内容明确标记。

## 入库建议

1. 提取 YAML 元数据，按科目和标签筛选；模板与本说明文件不作为学习内容入库。
2. 按标题小节切分正文，保持公式、代码块、题干及对应解析的完整性。
3. 给每个切片保留条目 ID、小节标题、文件路径和来源页码。
4. 使用 reviewed 状态区分已校对资料和 OCR 初稿，回答时显示引用。
5. 文档更新后按稳定 ID 更新索引，避免旧切片重复保留。

本仓库提供资料组织规范，不包含向量数据库或模型服务。
